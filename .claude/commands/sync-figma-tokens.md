Sync all color tokens in `src/theme/tokens.css` with the Figma Sapphire Theme source of truth.

## Arguments

- `$ARGUMENTS` — **(Required)** A Figma URL pointing to the Foundation/color section (e.g. `https://www.figma.com/design/<fileKey>/<fileName>?node-id=<nodeId>&m=dev`). The file key and node IDs change periodically as the Figma file is restructured, so there is no hardcoded default — the user must always provide the current URL.

## Key Files

- `src/theme/tokens.css` — Source of truth. All edits go here.
- `src/theme/sapphire-theme.css` — Auto-generated by build. Never edit manually.
- `.claude/skills/styling/SKILL.md` — Token naming conventions reference.

## Workflow

### Step 1: Read current tokens and styling reference

Read `src/theme/tokens.css` to understand the current state of all tokens.

Read `.claude/skills/styling/SKILL.md` for the token naming conventions and Figma-to-CSS mapping tables. Use these tables to correctly map Figma token names (e.g. `text/tertiary`, `icon/accent`) to CSS variable names (e.g. `--text-tertiary`, `--icon-accent`) and understand the alias hierarchy (shadcn base → sapphire semantic).

### Step 2: Fetch Figma colors

#### CRITICAL: Use the Variables API as the source of truth

**Never trust text labels or hex values from `get_design_context`.** The swatch card text labels in Figma are often stale or wrong — they show one hex while the actual fill is different.

Instead, use `get_variable_defs` on each section node to get the **true resolved variable values**. This returns the actual colors applied to the design, not the (potentially outdated) text annotations.

- Call `get_variable_defs` on each node to get resolved color values.
- Use `get_design_context` only for structural context (which tokens exist, how they're grouped) and screenshots — never for hex values.
- If `get_variable_defs` and a text label disagree, **always trust `get_variable_defs`**.

#### Fetching strategy

The Foundation node is large, so fetch child sections individually. **Node IDs and file keys change periodically** as the Figma file is restructured — never hardcode them.

1. Extract the `fileKey` and `nodeId` from the user-provided Figma URL.
2. Call `get_metadata` on the Foundation node to discover all child node IDs and their names.
3. Identify the sections by name: look for nodes named `Colors/Neutrals`, `Colors/Purples`, `Colors/Blues`, `Colors/Specific`, `Light Mode` (with children: Text, Chrome, Surface, Border, Notification, Buttons, Icon), `Dark Mode` (same children).
4. Call `get_variable_defs` on each identified section node.

**Maximize parallel calls** — fetch all base color nodes in one batch, all light semantic nodes in one batch, all dark semantic nodes in one batch. The `get_variable_defs` responses include ambient tokens from the surrounding context (e.g. `Text/text-primary` appears in every section) — only use the tokens that belong to the section being fetched.

### Step 3: Compare and update tokens

For each token, compare the Figma value against the current value in `tokens.css`.

#### CRITICAL RULES — Alias Preservation

**Base color scale tokens** (e.g. `--color-neutral-500`, `--color-blue-600`):
- These hold raw hex values. Update directly with the hex from Figma.
- Remove any `oklch()`, `hsl()`, or other formula-derived values — replace with actual hex.

**Brand tokens** (e.g. `--color-brand-blue`):
- If the brand token aliases a shadcn base token with the same value (e.g. `var(--primary)` where `--primary` is `#0070F2` and Figma says `#0070F2`), **keep the alias**.
- Only change if the Figma value differs from what the alias resolves to.

**shadcn base tokens** (e.g. `--card`, `--primary`, `--background`):
- If Figma shows a different value for something that a semantic token aliases, update the **base token**, not the semantic token.
- Example: if `--card-bg-primary: var(--card)` and Figma says card bg is `#FFFFFF` but `--card` is `#FEFDFF`, change `--card` to `#FFFFFF`. Do NOT change `--card-bg-primary` to `#FFFFFF`.

**Semantic tokens** (e.g. `--text-accent`, `--icon-neutral`, `--chrome-button-fg-selected`):
- These MUST remain as `var()` references. Never hardcode hex on a semantic token.
- If the Figma value maps to a different base token shade, update the alias: e.g. `var(--color-blue-700)` → `var(--color-blue-600)`.
- If the Figma value matches the current alias's resolved value, no change needed.
- **Exception:** If the Figma variable value doesn't map to ANY base token (e.g. `--card-bg-secondary` label says neutral-100 but variable is `#FFFFFF`), flag it to the user rather than silently picking one. The user may choose to hardcode the hex with an explanatory comment.

### Step 4: Apply edits

Edit `src/theme/tokens.css` with all identified changes. Update both `:root` (light) and `.theme-dark, .dark` (dark) sections.

### Step 5: Build

Run `npm run build` to regenerate `sapphire-theme.css`. The DTS error about `@ui5/webcomponents-localization` is pre-existing and can be ignored — CSS/JS bundles build fine.

**IMPORTANT:** After building, check `git status`. If `src/theme/sapphire-theme.css` changed, it MUST be committed alongside `tokens.css`. This file is auto-generated but tracked in git — Tailwind reads it at build time to know which utility classes to generate.

### Step 6: Report

Show a summary table of all changes:

```
| Token | Section | Before | After |
|-------|---------|--------|-------|
```

Group by: Base scales, Light semantic, Dark semantic.

### Step 7: Branch & PR (optional)

Ask the user if they want to create a branch and PR. If yes:
- Branch name: `ui/figmaTokenSync-$(date +%Y%m%d)` (append today's date to avoid conflicts on repeated runs, e.g. `ui/figmaTokenSync-20260408`)
- Commit both `src/theme/tokens.css` AND `src/theme/sapphire-theme.css` (if changed) — do not include unrelated staged files
- PR description should list all changes in a table format, and include the label-vs-variable mismatch table in a collapsible `<details>` section
